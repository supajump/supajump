# WorkClear — Domain Glossary

Canonical terms for code, UI copy, and documentation. Use these consistently.

---

## Platform & Tenancy

| Term | Definition | Code / table |
|------|------------|--------------|
| **Platform** | The WorkClear SaaS product operated by WorkClear staff | — |
| **Tenant** | A paying customer company | `organizations` where `type = 'organization'` |
| **Organization (org)** | Top-level tenant container; one org = one customer | `organizations` |
| **Org member** | Internal staff user belonging to a tenant | `org_memberships` |
| **Super org** | Internal WorkClear platform org for super-admins | `organizations` where `type = 'super'` |

---

## People & Parties

| Term | Definition | Notes |
|------|------------|-------|
| **Counterparty** | External party in the vendor registry (vendor, contractor, subcontractor, supplier) | Preferred **code/UI term**. Table: `counterparties` |
| **Vendor** | Informal/product term for a counterparty who performs work | Use in marketing copy; in code prefer "counterparty" |
| **Contractor** | A counterparty role tag, not a separate entity type | Stored in `counterparties.roles[]` |
| **Staff** | Org member who uses the WorkClear app | Has Supabase auth account |
| **Owner** | Tenant role with full access including billing | RBAC role: `owner` |
| **Super Admin** | WorkClear platform operator | Access via super org membership, not a tenant role |

**Rule:** Vendors/contractors are **never** org members. They interact only via upload tokens.

---

## Compliance

| Term | Definition | Values |
|------|------------|--------|
| **Compliance status** | Computed readiness of a counterparty to be dispatched | `pending`, `ready`, `warning`, `blocked` |
| **Pending** | No documents uploaded yet | — |
| **Ready** | All required docs present, verified, not near expiry | Dispatch allowed |
| **Warning** | At least one doc expires within 30 days | Dispatch allowed with caution |
| **Blocked** | Required doc missing, unverified, or expired | Dispatch blocked |
| **Requirement profile** | Org-level template defining required document types and rules | `requirement_profiles` |
| **Rule** | Single check within a profile (e.g. "COI must not be expired") | Stored in `rules_json` |
| **Verify / verified** | Staff confirmation that a document is acceptable | `documents.verified = true` |

Status is **computed**, not stored as truth on `counterparties`.

---

## Documents

| Term | Definition | Table / field |
|------|------------|---------------|
| **Document** | A compliance file (COI, W9, license, etc.) linked to a counterparty | `documents` |
| **Document type** | Category of compliance file | `documents.document_type` |
| **Expiry date** | When the document ceases to be valid | `documents.expires_at` |
| **Source** | How the document was added | `staff` or `upload` (vendor portal) |
| **Storage path** | Location in Supabase Storage bucket | `documents/{org_id}/{counterparty_id}/{doc_id}/filename` |

Documents are **append-only** — new uploads create new rows.

Common document types (MVP):

| Type | Description |
|------|-------------|
| `coi` | Certificate of Insurance |
| `w9` | IRS W-9 tax form |
| `license` | Trade or business license |
| `workers_comp` | Workers compensation certificate |

---

## Engagements & Dispatch

| Term | Definition | Table |
|------|------------|-------|
| **Engagement** | A scheduled job or work order linking a counterparty to a property | `engagements` |
| **Dispatch** | The act of sending a counterparty to perform work at a property | — |
| **Dispatch approval** | Manager sign-off that compliance status allows the engagement to proceed | `engagements.approval_status` |
| **Property** | Location where work will be performed | `engagements.property_name` (MVP) |
| **Approval status** | State of dispatch decision | `pending`, `approved`, `blocked` |

---

## Vendor Portal

| Term | Definition | Table |
|------|------------|-------|
| **Upload token** | Cryptographic link granting one-time vendor upload access | `upload_tokens` |
| **Upload link** | URL: `{APP_URL}/upload?token={token}` | Generated by staff |
| **Token expiry** | Default 7 days from creation | `upload_tokens.expires_at` |
| **Used token** | Token consumed after successful upload | `upload_tokens.used_at` |

---

## Notifications

| Term | Definition | Table |
|------|------------|-------|
| **Reminder** | Scheduled email nudging renewal or upload | `reminders` |
| **Reminder type** | What triggered the reminder | `expiry`, `missing` |
| **Reminder schedule** | Default: 30, 14, 7 days before expiry | Created on document insert |

---

## Billing

| Term | Definition | Notes |
|------|------------|-------|
| **Plan** | Subscription tier | `Starter`, `Growth`, `Pro` — must match Stripe product name |
| **Entitlement** | What a plan allows | Counterparty count cap |
| **Billing portal** | Stripe-hosted page for subscription management | Opened from Settings → Billing |
| **Limit** | Max counterparties for a plan | Starter = 50; enforced by DB trigger |

---

## Audit

| Term | Definition | Table |
|------|------------|-------|
| **Audit log** | Append-only record of significant actions | `audit_logs` |
| **Event** | Named action (e.g. `document_uploaded`, `engagement_approved`) | `audit_logs.event` |

---

## Naming Conventions in Code

| Concept | Preferred identifier |
|---------|---------------------|
| External party | `counterparty` / `counterpartyId` |
| Tenant | `orgId` / `org_id` |
| Compliance result | `ComplianceStatus` type with lowercase values |
| Feature folders | `src/features/counterparties/`, not `vendors/` |
| Query keys | `counterpartiesKeys.list(orgId)` |
